# 线性表的合并
合并两个顺序表或链表.
主要问题在于有序表的合并, 有序指的是该结构中的元素依据值的大小呈现递增或递减排列.

## 合并有序链表
由于链表指针的存在, 合并链表可以在不开辟新的内存空间的前提上进行.

基本思路: 因为链表合并不需要开辟新的内存空间即可完成, 所以本质上我们是选定其中一个链表作为完成后的结果, 我们称它为`主干链表`; 而另一个需要被拆解殆尽的称为`来源链表`; 主干链表原本就存在自己的元素, 所以它将被分为两部分, 已排序过的被称为`主干已确定部分`; 而未经过排序的"原住民"为`主干未确定部分`.

示例: 合并有序链表l1与l2, 升序排列, 维持时间复杂度在O(l1Length+l2Length);
```C#
// 传入两个链表的head以访问两个链表,
public static ListNode MergeSortedLists(ListNode l1, ListNode l2)
{
    if (l1 == null) return l2;
    if (l2 == null) return l1;

    ListNode head,           // 主干链表已确定部分的第一个节点
        tail,           // 主干链表已确定部分的最后一个节点
        curr,      // 主干链表未确定部分的第一个节点
        source;        // 来源链表的第一个节点

    if (l1.Value > l2.Value)
    {
        head = l2;
        tail = l2;
        curr = l2.Next;
        source = l1;
    } else {
        head = l1;
        tail = l1;
        curr = l1.Next;
        source = l2;
    }

    while (curr != null && source != null) // 主干链表存在未确定节点 && 来源链表未用尽
    {
        if (source.Value <= curr.Value) // 来源链表第一个值 小于等于 主干链表未确定部分第一个值
        {
            tail.Next = source; // 该来源链表未确定节点成为主干链表已确定部分的新增节点
            source = source.Next; // 来源链表未确定节点更新, 准备进下一轮循环
            tail.Next.Next = curr; // 主干链表已确定部分的新增节点(即tail.Next)来自source, 其next原本指向来源链表source，现在把它改接到主干未确定部分的第一个节点
            tail = tail.Next; // tail重新成为已确定部分的最后一个节点
        }
        else
        { // 来源链表第一个值 大于 主干链表未确定部分第一个值
            tail = curr; // 用主干链表未确定部分的第一个节点 替换 主干链表已确定部分的最后一个节点
            curr = curr.Next; // curr重新成为主干链表未确定部分的第一个节点
        }
    }

    // source 还有剩，整段接上
    if (source != null)
    {
        prev.Next = source;
    }

    return head;
}
```

## 合并有序顺序表
由于顺序表的存储须要连续的内存空间, 所以要完成该操作, 必须开辟新的内存.

我的老师曾举过一个例子"将一瓶醋和一瓶酱油对换瓶子, 需要几个瓶子?".

基本思路: 第三个表将作为结果存在, 而原表不需要改变, 这使得操作简介许多.
