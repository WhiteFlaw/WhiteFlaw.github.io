# 顺序表

## 顺序表的定义
一种在内存中利用连续地址依次存放数据元素，逻辑上相邻的元素，在物理内存中也相邻。

## 顺序表的结构特点
| 类型 | 特点 |
|---|---|
| 逻辑结构与物理结构一致 | 在顺序表中相邻的元素, 二者内存地址也相邻. |
| 支持随机访问 | 其逻辑结构与物理结构一致决定了其内部各元素所在位置是可以预计的, 直接通过下标能够准确访问. |
| 存储利用率高 | 不存在指针域之类额外占用内存空间的结构, 数据存储紧致, 内存利用率高. |
| 增删改效率低 | 每次增删改都需要移动其他元素, 对顺序表进行增删改的工作主要部分在移动元素. |
| 需要连续内存 | 物理结构与逻辑结构一致, 逻辑上需要存在不可中断的顺序关系, 物理结构上同样不可中断. |
|   适用场景   | 元素增删需要大量挪动, 适合查询多, 改动少的环境. |
|   并非是元素的顺序   | 顺序指的是在内存中具备顺序存储的特点, 而非此类结构内部的值具备规律. |

## 平均查找长度
下标未知的情况下在顺序表中查找一个值, 则需要遍历.那么在找到目标值之前定会进行与其他值的比较, 在一个顺序表中查找一个值, 平均需要与多少非目标值进行比较? 这便是平均查找长度.

### 平均查找长度公式
```
     n
ASL=∑    Pi×Ci
     i=1
```
i=1, 从第1个元素开始(与下标无关)遍历, 直到第n个元素, n为表长.
Pi: 该值被查找的概率.
Ci: 找到该值需要比较的次数(顺序遍历的话通常等于该元素的下标)

### 计算平均查找长度
现有1-100的数组, 查找第i个:
由于下标未知, 找到每一个元素的概率都是1/100, 所以Pi始终为1/100.
由于内部元素完全按照1-100顺序排列, 所以查1需要1次, 查2在第2次...以此类推Ci
     100
ASL=∑    ×(1/100)×Ci
     i=1
展开以上:
ASL= 1/100×1 + 1/100×2 + 1/100×3 + .... + 1/100×100
对于一个顺序表结构, 其平均查找长度固定, 而非受到"找第几个元素"的限制.

## 顺序表
实际上可以看作是JS数组
```C#
List<int> seqList = new List<int>(); // 声明整形列表

// 添加元素
seqList.Add(10);

// 按下标直接访问（O(1) 随机访问）
int val = seqList[1]; // 拿到 20

// 按值查找（O(n)，需要遍历）
int index = seqList.IndexOf(20); // 返回 1
```
